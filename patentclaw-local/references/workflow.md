# 从单篇论文到完整申请草稿

## 交付确认

G0前先确认文件数量与种类，默认推荐四份；已明确的用户选择直接沿用。介绍材料不包含具体训练超参数，以原理为中心，默认不引用消融结果；图件使用专业可编辑软件，缺真实效果来源时询问用户。详细规则见[写作与附图](writing-and-figures.md)。

## 阶段与门槛

| 阶段 | 本地角色与输入 | 产物及门槛 |
|---|---|---|
| G0 环境 | 协调者检查隔离/本地推理/同步/批准路径，不读正文 | privacy_contract有核验记录；缺证据即privacy_blocked |
| G1 摄取 | 本地解析者处理批准源包，OCR/提取可选 | 来源清单、定位证据、缺页/截断告警；无越界、静默缺失或截断 |
| G2 理解 | 理解者读全篇源证据 | 技术对象、目标、输入/步骤/输出、结构、训练/推理、实验条件和结论，逐项给证据 |
| G3 构思 | 发明提炼者依赖G2 | 问题—必要特征—关系—机制—条件性效果闭环，区分核心/可选/未知，不认定新颖性 |
| G4 方案 | 方案者依赖构思与证据 | S101…步骤、模块、数据流、符号、接口、约束与边界；核心缺口blocked，不补造 |
| G5 交底书 | 实施例与证据者→交底书作者 | 以原理和必要关系组织可实施方案；仅对确需的真实数据建立证据映射，原始训练参数留在本地证据 |
| G6 权利要求 | 申请作者依赖核验后构思/交底书 | 主权项必要特征及关系、从属项有依据限定，claim_support逐特征可追溯 |
| G7 说明书/图/摘要 | 作者依赖权利要求 | 说明书支撑全部权利要求，专业可编辑流程图加真实效果图，图文一致，摘要概括同一方案 |
| G8 独审 | 独审者读证据、图规格、实稿和映射 | 30项逐项结论和独立APP检查，缺失/语义未审不算通过 |
| G9 单问题改稿 | 每个check_id一个问题角色 | 最小补丁或blocked/no_change，串行验证合并，每轮全表复审 |
| G10 导出终审 | 本地导出者与独审者 | MD/JSON/DOCX、可编辑公式、中文附图和完整记录；导出后复核 |

G5交底书是完整申请稿的中间材料，G6—G7为本技能扩展，原项目exporter不替代它们。

核心事实缺失时可保存其他有依据内容为incomplete_draft；缺证据的特征不能进入正式权利要求。不可实施的主权项只以明确标记的候选讨论稿存审查目录，不能伪装正式权利要求。

## 角色合同

原五个Agent顺序执行：PaperUnderstanding→InventionMining→TechnicalSolution→EmbodimentEvidence→DisclosureWriter，可选第六独审，不能声称项目五个写作Agent并行。申请稿作者与专项审查为新增角色。

全部论文角色只能由经核验的本地人工/模型承担：

- 协调者冻结源、维护版本和状态，独占最终写入。
- 理解者整理原事实，发明提炼者组织概念而非认定创新性。
- 方案者组织已有实现，实施例者仅整理实际披露/验证的条件与结果。
- 作者转换结构而不扩大技术主体、范围与效果。
- 独审与作者分离，核验真实事实支持而非ID存在。
- 问题角色仅返回补丁；同base hash的并行提案串行合并，冲突重新定位或拒绝，不并行覆盖稿件。

仅提供必要本地证据切片。云端agent不能因为用户允许协作就接收保密论文；无本地agent时用人工角色。

## 申请稿扩展检查

存review/application_checks.json，不能混入原30项：

| ID | 要求 |
|---|---|
| APP-01 | 每个权利要求特征对应证据和说明书位置，排除未确认/unsupported；inherent有唯一必然推导和独立核验 |
| APP-02 | 主权项必要特征、关系及输入—技术处理—具体输出完整，不能删核心来降低问题 |
| APP-03 | 编号唯一，从属链有正确先行项且无环，术语/引用有先行基础，保护主题有依据 |
| APP-04 | 概括与实施支持相称，不从单值编范围、不由单一应用扩为全部领域 |
| APP-05 | 说明书覆盖权利要求，背景/方案/效果/图/实施方式一致，不掩盖缺口 |
| APP-06 | 摘要、摘要附图、节点、连线和标记对应最终方案，流程末端是具体结果，专业图源可编辑，效果图来源明确；缺源不伪造 |
| APP-07 | 导出后MD/JSON/DOCX语义一致，公式可编辑Office Math，图件、符号、单位和必要数值准确；介绍文件无具体训练超参数和非必要消融数据 |
| APP-08 | 身份/日期/权属/法律判断不猜测；草稿状态、待补材料、未检索现有技术和专业复核事项清楚 |

这是撰写质量合同，不是中国法律符合性判断。项目25字名称限制、至少3步、75分是仓库策略，不能写成普遍法律规则或机械扩写凑数。法规版本来自冻结策略，未实时法律核验；当前法律问题需专业人员核验，本流程不以保密内容联网检索。

## 状态与停止

原状态：pass/fail/needs_human_review/not_applicable/not_assessed。

- completed只代表流程结束；Reviewer passed仍可留minor/note问题；本技能ready要求适用项全通过。
- 18规则项通过、score=100、12项not_assessed，不能交付已终审。
- 当前事实满足该项才能no_change；缺事实是blocked。
- 最多3轮，无安全补丁停止；异常/超时不能改通过。
- 补原始缺口需新增真实材料、更新冻结来源，保留旧版本；不能清空unsupported_items伪造解决。

## 摄取与工具

源包先预检。单.tex输入原生成器会复制同目录全部.bib且不携带其他.tex章节；完整工程应使用明确批准的隔离源目录，不传论文父目录。PDF/Word需已安装且无出站的本地提取器，OCR疑点保留。

不调用Reviewer原生未经根约束的LaTeX读取器。可从安全解析的paper/evidence在本地构造ReviewInput，或先在隔离目录验证全部input/include和资产路径；不因missing warning继续正式成稿。

原offline是模板/关键词摘句，含通用alternatives和未经验证的数据流，仅用于解析/结构验证；每句模板仍需源证据。语义写作靠人工/已审计本地模型。

本地规则与导出只用审计版本的已安装依赖，不启用在线/回退。没有本地模型适配器时不得宣称已实现大模型离线自动写作；增加适配器须重新审计，不能默认原remote gateway安全。

## 介绍与工作记录分离

四份是推荐的对外交付数量，不包含本地中间交底书、证据和审查记录。合同验证器对完整流程仍核验中间disclosure记录；不因此默认给用户增加第五份文件。原始数字的证据定位不等于要求把每个数字写入介绍文件。
